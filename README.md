# Software Data Pipeline

用 Selenium 打开浏览器登录软件站，把列表页的软件信息采下来写进 MySQL，最后生成一份 HTML 分析报告。课程作业，Python 写的。

完整链路是：登录 → 采集（翻页 + 滚动加载）→ 入库 → 统计 → 出报告。

## 怎么跑

需要 Python 3.8+、本地 MySQL、Firefox。

```bash
pip install selenium requests pymysql
```

仓库里带了一份 `driver/Firefox/geckodriver.exe`。如果和你本机的 Firefox 版本对不上，去 [geckodriver releases](https://github.com/mozilla/geckodriver/releases) 下一个替换掉，版本不匹配会报 `SessionNotCreated`。`driver/Chrome/` 下那两个是早期尝试留下的，现在没用到。

改一下脚本开头的数据库账号密码，然后：

```bash
python Software_View_Sequence.py
```

第一次运行会提示输入账号密码，并在弹出的浏览器里要求手动拖一次滑块。跑完打开 `analysis/analysis_report.html` 看结果。

常用参数都在脚本前半段：`url` 是目标站点，`s_name` 是要采的栏目名，`page_max` 是页数上限（默认 3，想多采就调大）。

## 登录这块

滑块是手动拖的，没做轨迹模拟——脚本只负责把账号密码填进去、点开验证面板，等你拖完再自动点「继续」。

登录成功后会把 cookie 存到 `Cookie.json`，下次启动先试着用它恢复会话，恢复不了才走手动登录。判断依据是页面上有没有 `.user-menu` 这个元素，光看文件存在或条数不算数，因为未登录时也能拿到一堆界面偏好的 cookie。

存的时候只留 `name` / `value` / `domain` / `path` 四个字段。`sameSite` 的取值格式 Selenium 很挑，浏览器给的是 `no_restriction` 这种，回灌时会直接报错。

另外脚本**不会**在结束时点「退出登录」。退出会让服务端把 token 作废，刚存下的 cookie 下次就没用了。

`Cookie.json` 里是活的登录态，拿到它不需要密码就能进账号，所以不能提交到仓库。

## 数据

表名 `softwares`，六个字段：软件名、图标路径、作者、下载量、更新时间、简介。

下载量和更新时间存的是**原始文本**（`1.2万`、`3个月前`），清洗放在生成报告那一步做。这样统计口径要改的时候不用重新爬一遍。换算规则就是「万」乘一万、千分位去逗号，时间按天/月/年归到五个区间。

图标下载到 `img/`，数据库只存相对路径，报告直接引用本地文件。

## 已知问题

都写在代码里：

- 每次运行开头会 `drop database` 重建，不能增量更新，采到一半失败等于全丢
- 采集循环的 `try` 包住了整个 `for`，某一条数据出错会跳过这一页剩下的所有条目，而且只打印一行日志
- 时间分档没处理「今天」「昨天」「N周前」，这些记录被跳过，但百分比的分母还是全部条数，所以条形图加起来不到 100%
- 某条下载量如果是空串，`float('')` 会抛异常，而这时候数据已经入库、浏览器也关了，就差报告
- 无法无人值守，账号密码和滑块都得人来
- 全部逻辑写在一个文件里，从上到下跑，没有函数拆分

后面想做的：拆成 fetch/store/clean/report 四个模块、改成增量入库、采集逐条 try、用 Selenium Manager 自动匹配驱动。
